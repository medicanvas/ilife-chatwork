## 2. 報告書まとめの位置づけ（業務フロー）

| 段階 | 内容 |
|------|------|
| **通院** | 外部ヘルパーが利用者を通院に同行。 |
| **報告** | ヘルパーが LINE で通院報告を送る。 |
| **蓄積** | 報告内容を Chatwork の**患者ごとのルーム**に投稿し、時系列で溜めていく。 |
| **まとめ** | 過去の通院報告をもとに「**報告書まとめ**」を作成。 |
| **手渡し** | **次回の通院時**に、同行するヘルパーや医療機関に渡す資料として利用。 |

つまり「報告書まとめ」は、

- **誰が使うか**: 次に通院に同行する外部ヘルパー、必要に応じて病院・医師
- **いつ渡すか**: 患者が通院するとき（事前または当日）
- **何のためか**: これまでの受診内容・処方・医師の指示・生活上の注意を一覧にし、適切な介助・申し送りをするため

という役割を持つ資料です。

---

## 3. 報告書まとめの役割（なぜ必要か）

### 3.1 医療・介護の連携

- 障害者グループホームでは、**普段の様子を把握しているのは施設・ヘルパー側**で、本人が医師に状況を十分伝えられない場合が多いです。
- 医師が診療や処方の判断をする際に、「前回の受診以降、生活でどんな変化があったか」「前回の処方・指示の結果どうだったか」が分かると、診療の質が上がります。
- **通院時情報連携**（居宅介護支援の加算など）では、ケアマネ等が医師に「心身の状況・生活環境等の必要な情報」を提供し、医師からも必要な情報を受け取ることが推奨されています。

### 3.2 申し送り・引き継ぎ

- 通院のたびに**別のヘルパー**が同行する場合、前回・過去の通院内容が分からないと、病院での説明や介助がぶれます。
- 「報告書まとめ」を渡すことで、
  - どの科で何を相談してきたか
  - 処方の変更や副作用の指示
  - 次回予約や再診の注意
  を、新しいヘルパーも把握したうえで通院に臨めます。

### 3.3 記録の一元化

- LINE や口頭だけだと、後から「いつ・何が起きたか」を追いにくいです。
- Chatwork に報告を蓄積し、それを**一つの文書にまとめる**ことで、紙または PDF で手渡し・印刷しやすくし、施設・ヘルパー・医療機関の間で情報を揃えられます。

## 4. 一般的な様式・フォーマット（業界の慣行）

### 4.1 訪問介護の「通院介助記録」との違い

- **通院介助記録**: 1回の通院ごとに、**介護報酬の算定根拠**として作成する記録。  
  「算定可能時間／不可時間」「サービス内容と時間」「受診内容」を時系列で書く。主に事業所・行政向け。
- **報告書まとめ**: **複数回の通院報告を集約**し、**次の通院時に同行者や医療機関に渡す**ための「読み物」としての資料。  
  算定の細かい時間区分より、「何が起きたか・何に注意するか」が分かることが目的。

したがって、報告書まとめは「通院介助記録の様式」をそのまま使うというより、**複数回分の内容を時系列で並べた「申し送り・連携用のまとめ」** に近い形式が想定されます。

### 4.2 医療機関に渡す情報でよく使われる項目（参考）

通院時や入院時に介護側から医療機関へ情報提供する際、一般的に含まれるとされる内容は以下のようなものです。

| 項目 | 説明 |
|------|------|
| 日常生活動作（ADL）・生活状況 | 食事・排泄・移動などの支援状況、変化の有無。 |
| 服薬・処方 | 現在の服薬、変更の有無、副作用や自己中断の有無。 |
| 認知・行動 | 認知機能、行動面の変化、特記事項。 |
| 既往・医療情報 | 病名、主治医、かかりつけ、アレルギー等。 |
| 観察可能な事実 | 「ふらつきがある」ではなく「起立は3回目で成立。転倒歴あり」など、医師が判断しやすい記載。 |

報告書まとめでは、**過去の通院報告**から、上記のうち「受診内容・処方・医師の指示・生活上の注意」を抜き出して並べる形が自然です。

### 4.3 入院時情報提供書（様式）との関係

- 厚労省の**入院時情報提供書**では、生活機能、ADL、介護・医療の状況、今後の在宅生活の展望などを記載します。
- 報告書まとめは「入院時」ではなく**通院のたびに渡す**ものなので、様式をそのまま流用するより、**通院報告の蓄積から必要な項目だけを抜き出し、時系列でまとめた簡易版**と考えると整理しやすいです。

## 5. 想定される報告書まとめのフォーマット

Carelife の要件定義書および既存の ReportSummary モック、上記の業界慣行を踏まえた「報告書まとめ」の想定フォーマットです。

### 5.1 文書全体の構成

| 項目 | 内容例 |
|------|--------|
| **表題** | 「通院報告まとめ」「通院報告一覧」など。 |
| **利用者名** | 患者（利用者）の氏名。 |
| **対象期間** | 例: 直近3ヶ月、直近100件、〇月〇日〜〇月〇日。 |
| **作成日** | 報告書を作成した日付。 |

### 5.2 各回の通院報告（時系列で列挙）

1回ごとのブロックに、以下のような項目を含めます。

| 項目 | 内容例 |
|------|--------|
| **受診日** | 通院した日付。 |
| **受診先** | 病院名・診療科・担当医（分かれば）。 |
| **診察内容** | 処方の変更、検査結果、主治医の指示、次回予約など。 |
| **本人の様子** | 受診時の状態（安定、傾眠、不穏など）。生活上の変化があれば簡潔に。 |
| **申し送り・注意** | 服薬の注意、再診のタイミング、施設や次回同行者へ伝えたいこと。 |
| **担当者** | 報告したヘルパー・担当者名（任意）。 |

### 5.3 出力形式

- **プレビュー**: Web 画面上で 1 本のテキストとして表示し、編集可能にする。
- **印刷**: ブラウザの印刷で A4 等に出力。
- **保存**: テキスト（.txt）または PDF でダウンロード。

## 6. 既存の Carelife 実装との対応

- **ReportSummary.tsx** のモックでは、上記に近い項目（利用者名、受診先、診察内容、ご本人の様子、申し送り、担当者）がすでに使われています。
- **要件定義書_報告書まとめデモ.md** でも、表題・利用者・対象期間・通院報告一覧（時系列）・各回の内容・注意事項・申し送りが想定されています。

リサーチ結果として、**現状の想定フォーマットは、一般的な「通院時の情報連携・申し送り」の目的と整合しており、そのままデモや実運用のベースとして使って問題ない**と考えられます。

## 8. まとめ

- **報告書まとめ**は、**これまでの通院報告を時系列でまとめた「次回通院時に渡す資料」**であり、  
  **外部ヘルパーや医療機関への申し送り・情報連携**が主な役割です。
- 様式は「1回分の通院介助記録」ではなく、**複数回分の報告を、日付・受診先・診察内容・本人の様子・申し送りなどを揃えて並べた 1 本の文書**とするのが一般的な想定と合致します。
- フォーマットは、現在の Carelife の要件定義書および ReportSummary モックで想定している項目（表題、利用者、期間、各回の受診日・受診先・診察内容・様子・申し送り・担当者）をベースにし、実運用のフィードバックで項目の追加・文言の調整をしていく形が現実的です。

以上、リサーチ結果とします。
