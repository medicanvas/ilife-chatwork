# ケアライフ AI要約システム ご説明資料

**メディキャンバス × アイライフグループ**

---

## 1. このシステムは何をするものか

**一言でいうと：**
チャットワークに書かれた日々の支援記録を、AIが自動で読み取って「通院報告書」や「サマリー」を作ってくれるシステムです。

**今まで：**
```
チャットワークの記録を遡って読む
  → 手動でまとめる（30分〜1時間）
    → LINEやカレンダーに書き写す
```

**これから：**
```
ボタンを1つ押す
  → AIが自動で要約を作成（数十秒）
    → コピーしてLINEやカレンダーに貼るだけ
```

---

## 2. アイライフさんの課題と、このシステムでどう解決するか

| # | 現場の課題 | このシステムでどうなるか | 対応状況 |
|---|-----------|----------------------|---------|
| 1 | **通院報告書の作成に時間がかかる** | AIが記録から自動で報告書を作成。コピーしてすぐ使える | 動作中 |
| 2 | **区分認定の1年分の記録を手作業でまとめている** | AIが1年分の記録から、認定調査の5領域に沿って情報を整理 | 動作中 |
| 3 | **管轄利用者の1週間の変化を把握したい** | AIが1週間分の記録から週次サマリーを自動生成 | 動作中 |
| 4 | **支援記録の書き忘れを見つけたい** | 「編集中」のまま放置された記録を自動検知して通知（今後対応） | 開発予定 |
| 5 | **危険な兆候を見落としたくない** | AIが記録から発熱・発作・嘔吐・自傷などを自動検出して色分け表示 | 動作中 |

## 3. できること（現在の機能）

### 3-1. 週次サマリー

- 指定した期間の支援記録を時系列で整理
- 「安定 / 注意 / 要介入」の3段階で総合評価
- 身体面・精神面・生活面に分けてまとめ
- **出典付き**（どのスタッフが、いつ書いた記録が根拠か）

### 3-2. リスク検知

- 支援記録の中から危険な兆候を自動で見つけ出す
- 色分けで緊急度がひと目でわかる
  - **赤（緊急）：** 発熱38度以上、てんかん発作、嘔吐、自傷、誤嚥など
  - **黄（注意）：** 便秘3日以上、食事量の大幅減、睡眠の乱れ、副作用など
  - **緑（記録）：** 行動の変化、対人関係の変化、本人の発言など
- 各アラートに「推奨対応」を提示
- **出典付き**（どの記録に基づいているか明示）

### 3-3. 区分認定用エビデンス

- 障害支援区分の認定調査80項目・5領域に沿って情報を整理
  - 移動や動作等
  - 身の回りの世話
  - 意思疎通等
  - 行動障害（34項目・最重要）
  - 特別な医療
- **「支援が必要である根拠」を具体的なエピソードで示す**
- 数値化できるもの（発作回数、自傷回数など）は数値で表示
- **出典付き**（認定調査員への説明にそのまま使える）

### 3-4. 共通機能

| 機能 | 説明 |
|------|------|
| **利用者選択** | プルダウンから利用者を選ぶだけ |
| **期間指定** | 直近1週間 / 1ヶ月 / 3ヶ月 / 1年 / カスタム日付 |
| **追加の指示** | 「睡眠に注目して」などAIへの追加リクエストが可能 |
| **編集** | AIが作った文章はその場で修正できる |
| **コピーボタン** | ワンタップでクリップボードにコピー |
| **Chatwork送信** | 要約結果をチャットワークのルームに直接送信 |
| **スマホ対応** | スマートフォンのブラウザから操作可能 |

## 4. 仕組み（かんたんな流れ）

```
 【ステップ1】記録を貯める
 ┌─────────────────────────────────────────┐
 │  チャットワーク                            │
 │  （スタッフが毎日書いている支援記録）          │
 └────────────────┬────────────────────────┘
                  │
                  │  30分ごとに自動収集
                  ▼
 ┌─────────────────────────────────────────┐
 │  Googleスプレッドシート                     │
 │  （記録の保管庫 ＝ データベースの役割）        │
 │  message_id / 投稿者 / 本文 / 日時 ...     │
 └────────────────┬────────────────────────┘

 【ステップ2】要約を作る
                  │
                  │  必要な期間の記録を取り出す
                  ▼
 ┌─────────────────────────────────────────┐
 │  ケアライフ サーバー（クラウド上）            │
 │                                         │
 │  1. 期間で絞り込み                         │
 │  2. 業務連絡・雑談を自動除外                │
 │  3. Google Gemini（AI）に要約を依頼         │
 │  4. 要約テキストを返す                      │
 └────────────────┬────────────────────────┘

 【ステップ3】使う
                  │
                  ▼
 ┌─────────────────────────────────────────┐
 │  管理者のスマホ or パソコン                  │
 │                                         │
 │  要約を確認 → 必要なら修正                  │
 │  → コピーしてLINE / カレンダーに貼り付け     │
 │  → またはChatworkに直接送信                │
 └─────────────────────────────────────────┘
```

### 使われている技術（参考）

| 部分 | 技術 | 役割 |
|------|------|------|
| 記録の収集 | Google Apps Script（GAS） | チャットワークから30分ごとに記録を取得 |
| 記録の保管 | Googleスプレッドシート | メッセージを蓄積・保存 |
| AIによる要約 | Google Gemini | 記録を読んで報告書を生成 |
| サーバー | Google Cloud Run | クラウド上で処理を実行 |
| 画面 | React（Webアプリ） | 管理者が操作する画面 |
| 通信の暗号化 | HTTPS | データは暗号化されて通信 |

## 5. ノイズ除去とは

チャットワークのルームには、支援記録だけでなく以下のようなメッセージも混ざっています：

- 「来週のシフト表送りました」（業務連絡）
- 「お疲れ様です！」（挨拶）
- 「洗剤なくなりそうなので買ってきます」（雑談）

AIが要約を作るとき、**これらのノイズを自動で除外し、支援記録だけを読み取ります**。
管理者が手作業で記録を選り分ける必要はありません。

---

## 6. 出典（エビデンス）について

このシステムのAI要約には、すべて**出典**が付きます。

```
■ 身体面
・3/28 12:55頃、昼食中に噴出性嘔吐あり。未消化物混在。
  └ 記録: スタッフ高橋（3/28 12:55）
  └ 「突如として胃の内容物をすべて噴出するように嘔吐」
```

**なぜ出典が重要か：**
- 「AIが勝手に作った文章」ではなく、「どの記録に基づいているか」が明確
- 通院報告として医師に渡す際の信頼性が高まる
- 区分認定の調査員に対して「根拠」として提示できる
- 間違いがあった場合に元の記録を確認できる

## 7. できないこと・限界点

### 現時点での制約

| 制約 | 詳細 | 今後の対応 |
|------|------|-----------|
| **過去の記録** | システム導入前の記録は取得できません。蓄積開始日以降の記録のみ対象です | 導入後すぐに蓄積を開始すれば、日が経つほどデータが充実します |
| **記録がない期間** | スタッフが記録を書いていない日の情報はAIも把握できません | 記録書き忘れリマインド機能で対応予定 |
| **AIの誤り** | AIは完璧ではありません。事実と異なる要約を生成する可能性があります | **必ず管理者が内容を確認してから使用してください** |
| **画像・ファイル** | チャットワークに添付された画像やファイルの中身は読み取れません | テキストメッセージのみが対象です |
| **リアルタイム通知** | 現在は管理者がボタンを押して要約を取得する方式です。自動通知はまだありません | 週次サマリーの自動送信を開発予定 |
| **医療判断** | AIの出力は参考情報です。医療上の判断の代替にはなりません | 必ず医師・専門職の判断を優先してください |

### チャットワークAPI自体の制約

| 制約 | 影響 |
|------|------|
| 一度に取得できるのは最新100件まで | 30分ごとの定期収集で対応（通常100件を超えることはない） |
| 過去メッセージの一括取得・期間指定は不可 | 蓄積型（毎回新しい分を取って保存する方式）で解決 |
| Webhookは1アカウント5件まで | GAS定期収集と組み合わせて漏れを防止 |

## 8. セキュリティ・個人情報の取り扱い

| 項目 | 対応 |
|------|------|
| **通信** | すべてHTTPS（暗号化通信） |
| **記録の保管** | Googleスプレッドシート（Google Workspaceのセキュリティ基盤） |
| **APIキー** | サーバー側の環境変数で管理。画面やコードには含まれない |
| **要約結果** | サーバー側では保持しない。生成後はフロントに渡して破棄 |
| **アクセス制限** | スプレッドシートの共有設定で管理者のみに限定可能 |
| **NDA** | メディキャンバスとアイライフ間で秘密保持契約を締結予定 |

**重要：** このシステムでは利用者の個人的な支援記録を扱います。
運用にあたっては、アイライフ内部の個人情報管理規程に従ってください。

## 9. 利用の流れ（管理者向け）

### 初回セットアップ（1回だけ）

```
1. メディキャンバスからGASスクリプトを受け取る
2. Googleスプレッドシートに貼り付けて設定
3. チャットワークのAPIトークンとルームIDを登録
4. 「セットアップ」→「トリガー登録」を実行
5. 以降、30分ごとに自動で記録が蓄積されます
```

### 日常の使い方

```
1. スマホまたはPCのブラウザでケアライフにアクセス
2. 利用者を選ぶ
3. 要約タイプを選ぶ（週次サマリー / リスク検知 / 区分認定用）
4. 期間を選ぶ
5. 「要約を生成する」ボタンを押す
6. 数十秒でAI要約が表示される
7. 内容を確認・必要なら修正
8. 「コピー」してLINE/カレンダーに貼り付け、または「Chatworkに送信」
```

## 10. よくある質問

**Q. スタッフの書き方がバラバラでも大丈夫？**
A. はい。AIは多様な書き方を理解します。箇条書き、長文、時刻付き、略語混じりなど、実際の現場の記録をそのまま処理できます。

**Q. 1人あたりどれくらいの量の記録を処理できる？**
A. 1年分（数百件）の記録でも処理可能です。ただし、記録量が多いほど処理に時間がかかります（最大1〜2分程度）。

**Q. 要約の精度はどれくらい？**
A. 重要な事実（発熱、発作、服薬変更など）は高い精度で拾えます。ただし、文脈の解釈（皮肉や暗示的な表現）は苦手な場合があります。必ず管理者の確認をお願いします。

**Q. 利用料はかかりますか？**
A. 現在は無料でご提供しています。将来的な有料化の際は事前にご相談します。

**Q. インターネット環境は必要？**
A. はい。このシステムはクラウド上で動作するため、インターネット接続が必要です。

**Q. チャットワークの使い方は変わる？**
A. 変わりません。スタッフは今まで通りチャットワークに記録を書くだけです。管理者だけがこのシステムの画面を使います。
