# ケアライフ アーキテクチャ設計書（チャットワーク要約機能）

## 概要

チャットワークの支援記録メッセージを蓄積し、AI要約で通院報告書・区分認定要約を生成するシステム。

## データフロー詳細

### 1. メッセージ蓄積（GAS定期実行）

```
[30分おき]
  GAS → Chatwork API (force=0: 差分 + force=1: 最新100件)
      → 重複除去（message_id ベース）
      → スプレッドシートに追記

[フリープラン制約]
  - 40日以前のメッセージは取得不可
  - 蓄積開始が早いほどデータが増える

[ビジネスプラン（本番）]
  - 閲覧制限なし → force=0の差分取得で漏れなく蓄積
  - 30分間隔なら100件/回を超えることはほぼない
```

### 2. 要約生成（バックエンド）

```
フロント → POST /api/chatwork/summary
  {
    room_id: "425737026",
    period: "1month",        // 直近1ヶ月 / 3ヶ月 / 1年 / カスタム
    start_date: "2026-01-01", // カスタム時
    end_date: "2026-03-29",   // カスタム時
    summary_type: "visit_report" | "category_assessment" | "weekly"
  }

バックエンド処理:
  1. Google Sheets API でスプレッドシートからメッセージ取得
  2. 期間フィルタ（send_time で絞り込み）
  3. ノイズ除去（LLMで支援記録 vs 業務連絡を分類）
  4. Gemini で要約生成（summary_type に応じたプロンプト）
  5. テキストで返却

フロント → 要約テキスト表示（編集可）→ コピーボタン or 送信
```

### 3. Webhook蓄積（Cloud Run側 — フェーズ2）

```
[リアルタイム]
  チャットワーク → Webhook POST → Cloud Run /api/chatwork/webhook
      → スプレッドシートに追記 or Firestore に保存
      → リマインド判定（「編集中」「記入中」検知）

[制約]
  - Webhook上限: 1アカウント5件
  - 再送なし → GAS定期実行との二重化で補完
```

## API設計（新規追加分）

### バックエンド API

```
# チャットワーク要約関連
POST /api/chatwork/summary        — 要約を生成
GET  /api/chatwork/rooms          — 蓄積済みルーム一覧を取得
GET  /api/chatwork/messages       — メッセージ一覧（期間指定・ルーム指定）

# Webhook受信（フェーズ2）
POST /api/chatwork/webhook        — Chatwork Webhookの受信エンドポイント

# リマインド（フェーズ3）
POST /api/chatwork/remind/check   — 記録書き忘れチェック実行
```

{

## 技術選定

| 項目 | 選定 | 理由 |
|------|------|------|
| メッセージ蓄積先 | Google スプレッドシート | GASとの親和性、視認性、アイライフ側も閲覧可能 |
| バックエンドからの読み取り | Google Sheets API v4 | 既存のGCPプロジェクトで利用可能 |
| AI要約 | Gemini (既存) | 既にGEMINI_API_KEY設定済み。コスト効率◎ |
| Webhook受信 | Cloud Run (既存) | 追加インフラ不要 |
| 認証 | サービスアカウント (既存) | sa-key.json で既に設定済み |

### スプレッドシート vs Firestore

| 観点 | スプレッドシート | Firestore |
|------|---------------|-----------|
| セットアップ | GASと自然に連携 | 追加設定必要 |
| 視認性 | ◎ ブラウザで確認可能 | △ コンソール |
| クエリ性能 | △ 数万行まで実用的 | ◎ スケーラブル |
| アイライフ共有 | ◎ URLで共有 | × |
| 長期運用 | △ 10万行超は厳しい | ◎ |

**方針**: MVP〜初期運用はスプレッドシート。データ量が増えてきたらFirestoreへ移行を検討。
（北和35人 × 1日5件/人 × 365日 ≒ 64,000行/年 → スプレッドシートで1年は耐えられる）

## セキュリティ

| 項目 | 対応 |
|------|------|
| APIトークン | スクリプトプロパティ + 環境変数で管理。コードに埋め込まない |
| スプレッドシートアクセス | サービスアカウント経由。共有設定で制御 |
| 個人情報 | メッセージ本文には利用者の個人情報が含まれる → NDA締結必須 |
| HTTPS | Cloud Run はデフォルトHTTPS |
| データ保持 | 要約結果はフロントで表示後、サーバー側では保持しない方針 |
