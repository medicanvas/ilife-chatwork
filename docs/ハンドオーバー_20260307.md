## 1. プロジェクト概要

- **名前**: Carelife — 介護施設向け通院報告支援システム（MVP）
- **ルート**: このリポジトリのルート
- **目的**: LINE から起動し、録音 → 文字起こし（Speech-to-Text）→ AI要約（Gemini）→ 通院報告文の確認・編集 → LINE / Chatwork に送信する流れを実現する
- **現状**: 上記フローは **本番（Cloud Run）で一通り実装・稼働済み**。**Chatwork 連携**も実装済み（LINE から開いた場合は LINE＋Chatwork 両方へ、Chatwork のリンクから開いた場合は Chatwork のみへ送信）。環境変数（LINE / Chatwork / Gemini など）は **GCP の Cloud Run「変数とシークレット」** に登録済み。
- **本番 URL**:
  - フロントエンド: https://carelife-frontend-887034737640.asia-northeast1.run.app
  - バックエンド: https://carelife-backend-887034737640.asia-northeast1.run.app
  - LINE Bot: https://carelife-linebot-887034737640.asia-northeast1.run.app（Webhook は上記 + `/webhook`）

## 2. ここまでに完了していること

### GCP・環境
- **プロジェクト**: `yorisoi-demo`（請求有効化済み）
- **主なリソース**: Firestore（東京）、GCS バケット `yorisoi-demo-recordings`、Artifact Registry `carelife-repo`、サービスアカウント `carelife-backend-sa`
- **参照**: `docs/GCP環境構築計画_yorisoi-demo.md`

### アプリ（ローカル・本番ともに動作）
- **バックエンド**（`backend/`）: Node.js + Express。録音アップロード受信 → ffmpeg で WAV 変換 → GCS 保存 → Speech-to-Text V2（chirp_3）→ Gemini で通院報告要約。`POST /api/carelife/send-to-line` で **LINE および／または Chatwork** へ報告送信（`userId` があれば LINE、`chatwork_room_id` があれば Chatwork の指定ルームへ。LINE から開いた場合は両方に送信）。
- **フロントエンド**（`frontend/`）: Vite + React。患者名・担当者入力 → 録音 → 補足質問 → 報告作成 → 文字起こし・要約の表示・編集（**文章量に応じてテキストエリア自動リサイズ**）→ **「送信する」** で LINE または Chatwork または両方へ送信。URL の `userId` / `chatwork_room_id` で送信先を判別。**ステップ表示（例: ステップ 3/9）** で進捗が分かる。
- **LINE Bot**（`line-bot/`）: Webhook で「報告」等に反応し、報告作成用フロント URL（`?userId=...`）を返す。**受信したテキストを Chatwork の指定ルームに転送**する機能あり（環境変数 `CHATWORK_API_TOKEN` / `CHATWORK_ROOM_ID` で有効化）。

### Cloud Run デプロイ（完了済み）
- **carelife-backend**: ソースからビルド、PORT・GCS・Gemini・**LINE_CHANNEL_ACCESS_TOKEN**・**CHATWORK_API_TOKEN**・**CHATWORK_ROOM_ID**・サービスアカウントを設定済み。
- **carelife-frontend**: ビルド時に `VITE_API_BASE_URL` でバックエンド URL を埋め込み、静的配信。
- **carelife-linebot**: `FRONTEND_URL`、LINE の Channel Secret / Access Token、および **CHATWORK_API_TOKEN**・**CHATWORK_ROOM_ID**（LINE 受信テキストの Chatwork 転送用）を環境変数で設定。
- **デプロイ方法**: `scripts/deploy-cloudrun.ps1`（backend/.env から GEMINI_API_KEY、LINE_*、CHATWORK_* を読み込み、backend と line-bot に渡す）。
- **参照**: `docs/Cloud_Runデプロイ手順.md`

### その他
- **FFmpeg**: バックエンドの音声変換用。Windows では winget でインストール済みの想定。
- **TypeScript**: フロントで `import.meta.env` を使うため `src/vite-env.d.ts`（`/// <reference types="vite/client" />`）を追加済み。

## 5. Chatwork 連携（実装済み・今後の拡張）

### 実装済み
- **LINE から開いた場合**: 報告送信時に **LINE と Chatwork の両方** に送信（Chatwork は環境変数 `CHATWORK_ROOM_ID` のルームへ）。
- **Chatwork から開いた場合**: フロントの URL に `?chatwork_room_id=〇〇` を付けて開くと、**Chatwork の指定ルームにのみ** 送信（LINE には送らない）。
- **LINE Bot**: ユーザーが LINE で送ったテキストを、設定した Chatwork ルームに転送（「LINE から（1対1）」等の形式で投稿）。
- **詳細**: `docs/Chatwork連携テスト手順.md`、別途 `Chatwork/Chatwork_API分析_LINE連携.md`（API 仕様の整理）を参照。

### 今後の拡張（検討・未実装）
- **患者全体ルーム → 各患者ルームへの振り分け**: 患者全体ルームに溜まった報告を、メッセージ内容（利用者名など）を元に各患者用ルームへ自動投稿。Chatwork Webhook で新規メッセージを検知し、バックエンドで患者名パース・ルーム ID マッピングを行い投稿する構成が可能。要するに「患者名 → room_id」の対応表の管理方法と、フォーマットの統一が必要。
- **Chatwork 内でのテンプレート・AI 整形**: テンプレートをメッセージで配布しコピーして入力、または「投稿を Webhook で受け取り AI 整形して返信」は API 上可能。Chatwork 内にフォームや UI を埋め込むことは API では不可。

## 7. 技術メモ（引き継ぎ用）

- **バックエンド**: `backend/server.js`（PORT は環境変数、既定 8081）。finalize は `upload.single('audio')` で multipart 受信。GCS・STT・Gemini は `carelifeController.js` の `runSttAndReport`。
- **フロント**: API ベース URL は `import.meta.env.VITE_API_BASE_URL`（未設定時は `http://localhost:8081`）。Cloud Run ではビルド時に埋め込み。
- **LINE Bot**: `line-bot/server.js`。POST `/webhook` で 200 を即返し、非同期で reply。`FRONTEND_URL` を報告リンクとして返す。
- **プロジェクト ID**: `yorisoi-demo`。リージョンは `asia-northeast1`（東京）。
